# SVI — the Solana Valuation Interface

**AAPLx trades all night. Apple doesn't.**

A tokenized stock trades on Solana 24 hours a day. The share it represents
trades six and a half. Every night and every weekend, the token's price drifts
away from anything that reflects the company — and nothing on-chain says so. A
lending market that liquidates against the token's midnight price is
liquidating against a number no exchange agrees with.

SVI puts the true value on-chain. For each stock, one transaction reads two
Pyth feeds — the real equity (`Equity.US.AAPL/USD`) and the token
(`Crypto.AAPLX/USD`) — and publishes two verifiable quote accounts anyone can
read, carrying Pyth's confidence interval as bounds and flagged
`MARKET_CLOSED`, `REFERENCE_STALE`, `TOKEN_FEED_STALE` or `DEVIATION_HIGH`.

There is no API to trust. The accounts are on-chain, the math is on-chain, and
`tools/stock-check` will re-run it against Pyth without using a line of SVI's
code.

---

## What gets published

Two accounts per symbol, written in the **same instruction**, so the pair can
never be half-updated:

| feed | `value_type` | what it is |
|---|---|---|
| `stock-<sym>-fair-value-v1` | `ReferenceFairValue` (7) | what the real share is worth |
| `stock-<sym>-market-v1` | `MarketSpot` (2) | what the token trades at on Solana |

Each carries `value`, `lower`, `upper`, `observed_slot`, `valid_until_slot`,
`sequence` and `status_flags` in a frozen 320-byte layout.

### The flags, and what each one means

Bits 16–23 are the stock adapter's, registered in `svi-core::state::flags` so
two adapters can never mean different things by the same bit. (Bits 0–5 are
the Hylo adapter's.)

| bit | flag | raised when |
|---|---|---|
| 16 | `MARKET_CLOSED` | the equity price is older than 15 minutes — during a session that cannot happen, so it means the exchange is shut |
| 17 | `REFERENCE_STALE` | older than 4 days, which no ordinary closure explains |
| 18 | `TOKEN_FEED_STALE` | the token feed has gone quiet, which it never should |
| 19 | `DEVIATION_HIGH` | the token is more than 2% away from the real share |

A flag is a thing worth reporting. A **refusal** is different: past
`reference_max_age_secs` (8 days) or outside the confidence tolerance, the
adapter publishes nothing at all. *Fail stale, never fail wrong* — a visibly
expired quote is always better than a plausible wrong one.

## The dashboard

`site/index.html`, deployed from the repository root via `netlify.toml`.

It reads the quote accounts **from your browser**, over a public Solana RPC,
with no backend and no API key. The same `getMultipleAccounts` call works from
your terminal, and every address is on the page.

```bash
cp deployments.json site/deployments.json
python3 -m http.server -d site 8080
node --test site/test/*.mjs          # the decoder, checked against the frozen layout
```

## Running the keeper

Cranking is permissionless. The keeper holds no privileged key: `svi-core`
accepts the write only because the **adapter's own PDA** signed the CPI, and
the keeper cannot influence the value. Anyone can run this.

```bash
cargo run --manifest-path tools/svi-keeper/Cargo.toml -- \
    crank --feed stock:AAPL --interval 30

cargo run --manifest-path tools/svi-keeper/Cargo.toml -- \
    watch --feed stock:AAPL
```

Two ways to get a price on-chain, and the choice is recorded on-chain rather
than in a config nobody else can see:

- **default** — read Pyth's *sponsored* price accounts. Pyth keeps them fresh
  and they carry **Full** verification (two thirds of the guardian set).
- **`--post-updates`** — fetch a signed update from Hermes and post it. Needed
  when a feed is not sponsored on your cluster, which is the usual case for
  `Equity.US.*` on devnet. A single-transaction post checks a subset of
  signatures, so it yields **Partial** verification; a symbol cranked this way
  must have `min_verification_level = 0` in its on-chain config, where a
  consumer can read it.

## Verify it yourself

```bash
cargo run --manifest-path tools/stock-check/Cargo.toml -- AAPL
cargo run --manifest-path tools/stock-check/Cargo.toml -- --self-test
```

`stock-check` depends on **none** of SVI's crates. Its scaling arithmetic is
written out again from Pyth's documented exponent convention, and its
self-test pins 16 vectors against `svi-math` — the code the on-chain adapter
actually runs. Two implementations agreeing is evidence; one implementation
agreeing with itself is not.

It reads the published accounts, asks Hermes independently what the feeds say,
and complains if a quote is outside its own bounds, mistyped, or if the pair
was not written at the same slot.

## Reading a quote in your own program

About 200 compute units, one account, no CPI:

```rust
let q = &ctx.accounts.svi_quote.data.borrow()[8..];

let valid_until = u64::from_le_bytes(q[280..288].try_into()?);
let flags       = u64::from_le_bytes(q[296..304].try_into()?);
let base_amount = u64::from_le_bytes(q[224..232].try_into()?);
let lower       = u64::from_le_bytes(q[240..248].try_into()?);

require!(Clock::get()?.slot <= valid_until, MyError::StaleQuote);
require!(flags & HALT_MASK == 0,            MyError::FeedHalted);

// value = your amount * lower / base_amount — no decimals hardcoded.
let collateral_usd = amount as u128 * lower as u128 / base_amount as u128;
```

### The Quote layout

320 bytes of payload after an 8-byte discriminator. Offsets below are
**relative to the payload**, which is how you index after `data[8..]`. The
layout is frozen and asserted by `svi-core/tests/core.rs::layout_is_frozen`; a
change would be a new feed, not a new version of this one.

| offset | size | field |
|---|---|---|
| 0 | 32 | `descriptor` |
| 32 | 32 | `feed_id` |
| 64 | 32 | `base_mint` |
| 96 | 32 | `quote_mint` |
| 128 | 32 | `adapter_program` |
| 160 | 32 | `methodology_hash` |
| 192 | 32 | `source_accounts_hash` |
| **224** | 8 | **`base_amount`** — what the price is quoted *per* |
| **232** | 8 | **`quote_amount`** — the value |
| **240** | 8 | **`lower_quote_amount`** — use this for collateral |
| **248** | 8 | **`upper_quote_amount`** — use this for debt |
| 256 | 8 | `observed_slot` |
| 264 | 8 | `observed_unix_ts` |
| 272 | 8 | `published_slot` |
| **280** | 8 | **`valid_until_slot`** — refuse past this |
| 288 | 8 | `sequence` |
| **296** | 8 | **`status_flags`** |
| 304 | 2 | `quote_currency_code` (840 = USD) |
| 306 | 1 | `value_type` |
| 307 | 1 | `base_decimals` |
| 308 | 1 | `quote_decimals` |
| 309 | 1 | `version` |
| 310 | 1 | `bump` |
| 311 | 9 | padding |

## Sponsor tracks

### Pyth

Pyth is the only price source, and it is used as more than a number:

- **Two feeds per symbol, read in one transaction.** The equity feed and the
  token feed are read together so the drift between them is measured at a
  single instant, not across two reads.
- **Confidence intervals become the published bounds.** Pyth's `conf` is
  carried through into `lower`/`upper` with asymmetric rounding — the lower
  bound floors, the upper ceils — so the published band is never tighter than
  Pyth's. A quote whose confidence exceeds 500 bps is refused outright: an
  oracle that unsure is not publishing a price.
- **Verification level is enforced and recorded.** The adapter checks
  `VerificationLevel` against a per-symbol on-chain minimum and defaults to
  requiring `Full`. Where a deployment must post its own updates, the weaker
  level is written into the config where consumers can see it.
- **Feed identity is checked on-chain, every refresh.** The 32-byte feed id
  inside the price account is compared to the one in the symbol's config. A
  keeper chooses which accounts go into a transaction, so without this check
  anyone could pass a real, fully verified price for a *different, cheaper*
  asset and have it published as AAPL's.
- **Feed ids are fetched from Hermes at build time**
  (`scripts/fetch-feed-ids.py`), never typed from memory, and the file records
  the URL and timestamp they came from.
- **`--post-updates`** implements the full Hermes → `post_update_atomic` →
  refresh path, including trimming the Wormhole VAA's signature list to fit
  Solana's packet limit.

## Adapter #2: it already generalises

Before stocks, SVI published the NAV of Hylo's xSOL — a number computed by
*subtraction* from a protocol's own vault, nothing like a Pyth feed. Same
core, same 320-byte account, same write path; only the adapter differs.

On 10 September 2026 it published a real quote on a mainnet fork with Hylo's
accounts re-cloned seconds before, and an independent off-chain reader agreed
to the last digit: `$0.060285498`. The full record is in
[`docs/validation/2026-09-10-xsol-nav-mainnet.md`](docs/validation/2026-09-10-xsol-nav-mainnet.md).

That is the argument for calling this an *interface* rather than an oracle.
